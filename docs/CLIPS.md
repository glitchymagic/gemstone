## Throws (kind 4)

A throw's victim motions sit in the THROWER's Pn0_MOT.MDT kind-4 table (e.g. Falcon's table holds his own k4/0
slot and the victim id 49; no fighter has another thrower's victim ids), and the game plays them on the victim's
skeleton. So they are captured on the thrower in Motion Check (pass C: the fighter's whole kind-4 table + id 0)
and tools/victim_clips.py copies them onto every fighter like the game does (joints 0-18 local rotations + the
root channel; the victim's other parts at his idle pose): clip <victim prefix>k4_<id>_<thrower prefix>, e.g.
r0k4_049_f0 = Ryoma thrown by Falcon. Slot 0 is the first entry of every table (offset 0), so k4/0 is real.

## In-fight captures (fight_clips.py) (fx-item2 helper, 2026-10-27)

Motions whose Pn0_MOT.MDT slot is empty (Motion Check replays idle) are recorded from a REAL fight instead:
`tools/fight_clips.py` boots the tape's fight on an isolated instance (reflog.boot), takes a RAM dump at the round
intro to find the fighter's part records (the MDL copy / record group whose root sits nearest that player), plays the
tape with both pads human (rand 1, reflog.play's start) and capsegs the part records + the player struct (motion block
+0x7190..+0x71C0, feet +0x020, facing +0x7248, model matrix +0x06C) from a tape row on; then cuts each wanted id by the
player's own kind / id / motion counter. Same clip format as tools/clips.py, merged by `add_clips.build(..., pre=)`.
- Base per frame = the model matrix +0x06C (feet + the yaw the body is drawn with; +0x7248 is not it: in Ryoma's kick
  k1/24 the body turns to the opponent while +0x7248 stays, 137 deg root error with it). Clip frame 0 = motion count 1
  and a one-shot ends with its last pose held once (the Motion Check convention); a loop = the counter wraps with the
  id held, one period, each count from the row held longest (the game blends ~3 frames after a motion switch).
- Parts the game leaves unposed in a motion (world matrix unchanged while the root moves: unselected hand variants,
  Ryoma's sword parts 23/24 while he holds an item) are kept at rest and listed as `stale` in the clip index; the hand
  variant the game posed goes to `sel` (make_clipmap.py writes it into pN_clips.json "variants": r0 item clips
  [0, 2, 0] / gun family [0, 2, 1]). The original does not draw parts 23/24 during the item motions (the remaster
  still shows them: game side).
- Check against motions Motion Check DID capture (`fight_clips.py compare`, same in-fight capture): Ryoma k2/229, k2/235,
  k1/16, k1/24 max 0.03 deg on every joint, root 0.0 cm, same lengths (25 / 36 / 31 / 33); loops k0/0 (69) and k2/230
  (60) 0.03 deg on every joint except the head. **Head (joint 4)**: in state-0 idles / holds the original turns the
  head 22-73 deg away from the Motion Check data (Ryoma k0/0 22-26 deg with the opponent straight ahead, k2/230 73 deg),
  so the in-fight hold loops (k2/238, k2/81) carry the head pose of their capture; attacks / pick-ups / throws match.
  Ground attacks that travel: the game moves the base, so the in-fight root lacks the travel Motion Check clips carry
  (k1/24: 60 cm); none of the clips added here travels (k2/245, k2/86 stand still; k1/10 is airborne).
- Item ids: the chest's item comes from the C rand, which in our cap1 runs diverges from the o_ logs from frame 2
  (items_weapon gave item 2, items_id7's chest poke at 900 gave item 0); `tools/fight_clips.lua` adds tape row
  commands `@itemid N` (every floor item -> id N), `@toitem P DX DZ ANG` (stand next to the nearest floor item),
  `@faceme P DIST`; the tapes tools/fight_clips_tapes/hold_idN.tape (items_weapon's timeline: pick up at 985, hold 100
  frames, walk DOWN 60, 3 X) force items 1 / 2 / 7 (a run without a floor item at 985 is just re-run).
